SELFISHNET v2 - CÓMO FUNCIONA
Una guía sencilla para entender qué hace esta aplicación y cómo funciona.

--------------------------------------------------------------------
1. QUÉ HACE ESTA APLICACIÓN
--------------------------------------------------------------------
SelfishNet v2 es una herramienta para controlar el tráfico de red en una LAN (red de área local) desde Windows.
Desde una sola PC conectada a tu red, puedes:

  - Ver los dispositivos conectados a tu red local (dirección IP, dirección MAC y nombre).
  - Limitar la velocidad de descarga y subida de cada dispositivo.
  - Bloquear por completo el tráfico de red de un dispositivo.
  - Ver gráficos en tiempo real del ancho de banda de toda la red y de cada dispositivo.

La aplicación funciona a bajo nivel. En lugar de configurar el router, redirige temporalmente el tráfico de los dispositivos seleccionados a través de tu computadora mediante una técnica llamada suplantación de ARP (ARP spoofing). Tu computadora se encarga de reenviar ese tráfico aplicando los límites de velocidad que hayas configurado.

Cuando presionas Stop o cierras la aplicación normalmente, SelfishNet envía mensajes ARP correctivos para ayudar a restablecer las asociaciones de red originales.

Entre sus usos habituales están comprobar cómo se comporta una aplicación con una conexión lenta, limitar el ancho de banda disponible para un dispositivo invitado o aprender cómo funcionan las redes locales. Utiliza esta herramienta únicamente en redes de tu propiedad o para las que tengas autorización expresa para realizar pruebas.

--------------------------------------------------------------------
2. LA IDEA PRINCIPAL: ARP Y EL «ATAQUE DE INTERMEDIARIO»
--------------------------------------------------------------------
En una LAN, los dispositivos utilizan direcciones IP para identificar los destinos de red, pero las tramas Ethernet también necesitan la dirección física del destino, conocida como dirección MAC. El protocolo que relaciona una dirección IPv4 con una dirección MAC se llama ARP (Protocolo de resolución de direcciones).

Cuando una computadora necesita enviar tráfico al router, transmite una solicitud ARP a la red local: «¿Quién tiene la dirección 192.168.1.1? Indícame tu dirección MAC». El router responde con su dirección MAC, y la computadora guarda temporalmente esa asociación en su caché ARP.

ARP fue diseñado sin un mecanismo de autenticación integrado. Por eso, algunos dispositivos pueden aceptar respuestas ARP falsificadas y actualizar sus cachés con asociaciones incorrectas entre direcciones IP y MAC.

SelfishNet aprovecha este comportamiento. Para cada dispositivo que selecciones, envía dos respuestas ARP falsificadas principales:

  1. Al dispositivo:  «La dirección IP del router está asociada con MI DIRECCIÓN MAC».
  2. Al router:        «La dirección IP de ese dispositivo está asociada con MI DIRECCIÓN MAC».

Si ambos aceptan estas asociaciones falsificadas, comienzan a enviar a tu computadora el tráfico que originalmente debía ir directamente del uno al otro. Tu computadora queda situada entre el dispositivo y el router. Esta técnica se conoce como suplantación de ARP (ARP spoofing), y la posición resultante se denomina ataque de intermediario (man-in-the-middle o MITM).

La aplicación vuelve a enviar periódicamente respuestas ARP falsificadas para mantener la redirección, ya que los dispositivos pueden actualizar sus cachés ARP o recibir información ARP contradictoria. El intervalo es de 2 segundos con el motor Modern y de 5 segundos con el motor Legacy.

El motor Modern también incorpora una defensa ARP reactiva que responde a determinados eventos ARP que podrían deshacer la redirección.

Cuando la aplicación se detiene, las asociaciones ARP falsificadas pueden permanecer hasta que sean reemplazadas o caduquen. SelfishNet también envía mensajes ARP correctivos al detenerse para ayudar a restablecer las asociaciones originales (consulta la sección 6).

--------------------------------------------------------------------
3. CÓMO SE REENVÍA Y SE LIMITA EL TRÁFICO
--------------------------------------------------------------------
Mientras la aplicación está situada entre un dispositivo controlado y el router, recibe el tráfico que se ha redirigido a través de tu computadora. Para cada paquete, determina qué hacer según su dirección, la configuración del dispositivo y los límites de ancho de banda establecidos.

  Descarga (router -> dispositivo):
    El paquete llega desde el router y está destinado a un dispositivo
    controlado. Si el dispositivo está bloqueado o se ha alcanzado el
    límite de ancho de banda correspondiente, el paquete se descarta.
    De lo contrario, la aplicación cambia la dirección MAC de destino
    por la dirección MAC real del dispositivo y reenvía el paquete.

  Subida (dispositivo -> router):
    El paquete se origina en un dispositivo controlado y está destinado
    al router. Se aplica la misma regla: si el dispositivo está
    bloqueado o se ha alcanzado su límite de ancho de banda, el paquete
    se descarta. De lo contrario, la aplicación cambia la dirección MAC
    de destino por la dirección MAC real del router y reenvía el paquete.

  Tráfico de tu propia PC:
    Se contabiliza en las estadísticas, pero la aplicación no lo vuelve
    a reenviar.

La aplicación ofrece dos motores de control de tráfico, que aplican los límites de ancho de banda de manera diferente:

  MOTOR LEGACY
    Es una implementación fiel de los mecanismos del programa original
    de 2007. Aplica los límites mediante intervalos fijos de 1 segundo.
    Al comienzo de cada segundo, se restablece el cupo de transferencia
    del dispositivo. Una vez consumido ese cupo, los paquetes
    adicionales se descartan hasta que comienza el siguiente segundo.

    Este método es sencillo y predecible, pero puede generar ráfagas de
    tráfico seguidas de períodos en los que se pierden paquetes.

    El motor Legacy conserva el comportamiento original al procesar
    paquetes, incluida su secuencia de cuatro tramas ARP para la
    suplantación. No utiliza la defensa ARP reactiva del motor Modern y
    no ofrece el mismo procesamiento compatible con tráfico etiquetado
    con VLAN.

  MOTOR MODERN (predeterminado)
    Utiliza el mismo enfoque básico de suplantación de ARP y reenvío de
    paquetes, pero ofrece un control del ancho de banda más gradual
    mediante un algoritmo de depósito de tokens (token bucket).

    Los tokens se acumulan continuamente según la velocidad
    configurada, hasta alcanzar la capacidad máxima del depósito.
    Un paquete solo puede reenviarse cuando hay suficientes tokens
    disponibles. Esto ayuda a reducir el comportamiento irregular del
    motor Legacy.

    El motor Modern también admite tráfico IPv4 etiquetado con VLAN y
    utiliza una defensa ARP reactiva para responder a determinados
    eventos que podrían restablecer las asociaciones originales.
    Su secuencia de suplantación omite una trama inactiva que el motor
    Legacy conserva por compatibilidad con el programa original.

Puedes cambiar de motor en cualquier momento desde la barra de herramientas. Al hacerlo, la aplicación detiene el control del tráfico, intenta restablecer las asociaciones ARP originales, cierra el motor actual, inicia el otro y reanuda la operación.

Los dispositivos detectados, los límites configurados y los nombres personalizados se conservan al cambiar de motor.

Los límites de velocidad se pueden introducir en KByte/s o KBit/s mediante el selector de unidades de la barra de herramientas. El valor 0 significa sin límite. Internamente, los límites se almacenan como números enteros de bytes por segundo, por lo que cambiar las unidades de visualización no modifica el límite de ancho de banda configurado, salvo los posibles efectos del redondeo al mostrar o introducir valores enteros.

4. QUÉ DATOS LEE LA APLICACIÓN (Y CUÁLES NO)
--------------------------------------------------------------------
La aplicación inspecciona las cabeceras de los paquetes Ethernet e IP para identificar direcciones, clasificar el tráfico, modificar direcciones MAC al reenviar paquetes y medir las velocidades de transferencia. No descifra el tráfico de las aplicaciones ni serializa el contenido de los paquetes para guardarlo en disco.

Los datos persistentes de la aplicación se guardan en dos archivos:

  - %AppData%\SelfishNetV2\settings.json
    Guarda la configuración de la aplicación, incluidos el idioma,
    el tema visual, las unidades de ancho de banda, el último adaptador
    de red utilizado y el motor seleccionado.

  - %AppData%\SelfishNetV2\known_devices.json
    Guarda información de los dispositivos conocidos asociada a sus
    direcciones MAC, incluidos los nombres personalizados, los límites
    de ancho de banda, los estados de las opciones Block y Spoof,
    la última dirección IP conocida y la información de la última vez
    que se detectó cada dispositivo.

La aplicación no genera archivos de registro de diagnóstico ni del tráfico de red.

--------------------------------------------------------------------
5. DETECCIÓN DE DISPOSITIVOS
--------------------------------------------------------------------
Al iniciarse, la aplicación busca dispositivos en la subred local y repite el escaneo aproximadamente cada 60 segundos. Envía solicitudes ARP a las direcciones de la subred y escucha las respuestas para identificar los dispositivos activos.

La aplicación también detecta dispositivos de forma pasiva al supervisar el tráfico ARP que ya circula por la red. Así, muchos dispositivos pueden aparecer sin necesidad de iniciar un escaneo manual.

El botón Discover inicia un escaneo inmediato. Los nombres de los dispositivos se obtienen mediante consultas DNS inversas cuando están disponibles. Puedes cambiar el nombre de un dispositivo haciendo doble clic sobre su nombre. Los nombres se guardan asociados a la dirección MAC, por lo que siguen vinculados al mismo dispositivo aunque cambie su dirección IP.

--------------------------------------------------------------------
6. CÓMO DEJAR LA RED EN SU ESTADO ORIGINAL (RESTAURACIÓN)
--------------------------------------------------------------------
Cuando se detiene el control del tráfico, los dispositivos pueden conservar entradas en sus cachés ARP que asocian la dirección IP del router con la dirección MAC de tu computadora, y viceversa. La aplicación intenta corregir estas asociaciones enviando mensajes ARP con las direcciones MAC reales.

El procedimiento de restauración incluye:

  - 35 pares de mensajes ARP correctivos unicast entre cada dispositivo
    controlado y el router.
  - 3 anuncios ARP por broadcast para el router y 3 para cada
    dispositivo. Estos anuncios intentan actualizar las cachés ARP,
    incluso en equipos que no respondieron a las correcciones unicast.

La aplicación registra los dispositivos cuyas asociaciones ARP ha modificado, independientemente del estado actual de sus casillas de selección. Esto ayuda a evitar que algún dispositivo quede fuera del proceso de restauración.

Si desmarcas un dispositivo mientras la sesión está activa, la aplicación intenta restaurar inmediatamente sus asociaciones ARP. Detener el control del tráfico, cambiar de motor, cambiar de adaptador de red o eliminar un dispositivo del catálogo activo también activa el procedimiento de restauración correspondiente.

Antes de realizar la restauración, la aplicación intenta resolver la dirección MAC del router si ya no la conoce. Si no consigue completar la restauración, conserva el registro del dispositivo afectado para volver a intentarlo cuando sea posible.

Si la aplicación se termina por la fuerza, por ejemplo, desde el Administrador de tareas o debido a un corte de energía, no puede realizar esta limpieza. Las entradas ARP falsificadas pueden permanecer hasta que sean reemplazadas o caduquen. El tiempo que tardan en hacerlo depende del dispositivo y del sistema operativo.

Al utilizar Stop o cerrar la aplicación normalmente, SelfishNet tiene la oportunidad de enviar los mensajes ARP correctivos antes de salir. Sin embargo, la restauración no se puede garantizar en todos los entornos de red.

--------------------------------------------------------------------
7. REQUISITOS PARA EJECUTAR LA APLICACIÓN
--------------------------------------------------------------------
  - Windows 10 u 11. Hay versiones disponibles para Windows de 64 y
    32 bits. En una PC moderna con Windows de 64 bits, utiliza la
    versión x64.
  - Npcap (https://npcap.com) o el antiguo WinPcap. Npcap es el
    controlador moderno y firmado para la captura de paquetes. La
    aplicación detecta automáticamente el controlador disponible.
    Es el único componente externo necesario para capturar y enviar
    paquetes de red en vivo.
  - Según la configuración del controlador de paquetes, puede ser
    necesario contar con permisos de administrador. Normalmente,
    la aplicación se inicia sin privilegios elevados, comprueba si
    puede acceder al controlador y, si se deniega el acceso, ofrece
    reiniciarse con permisos de administrador.

SelfishNet se distribuye como un ejecutable portátil, por lo que no requiere una instalación independiente de .NET.

8. LIMITACIONES Y CASOS ESPECIALES CONOCIDOS
--------------------------------------------------------------------
  - Solo se puede administrar un adaptador de red y una subred a la vez.
  - Solo admite IPv4; el tráfico IPv6 no está soportado.
  - Los dispositivos deben estar en el mismo segmento de red local
    (capa 2).
  - El motor Modern admite tráfico IPv4 etiquetado con VLAN. El motor
    Legacy conserva el procesamiento de paquetes con desplazamientos
    fijos del programa original y puede no procesar correctamente
    el tráfico etiquetado con VLAN.
  - La limitación de subida depende de que el dispositivo acepte la
    respuesta ARP falsificada y de que la aplicación conozca la
    dirección MAC correcta del router. Si el dispositivo ignora la
    respuesta falsificada, su tráfico de subida puede no quedar
    limitado aunque la limitación de descarga funcione.
  - Algunas redes Wi-Fi tienen activado el aislamiento de clientes
    o mecanismos de protección ARP. Estas funciones pueden impedir
    la suplantación de ARP o bloquear la comunicación entre dispositivos
    necesaria para que funcione esta técnica. Se trata de una
    limitación de configuración o compatibilidad de la red, no
    necesariamente de un error de la aplicación.
  - Si el reenvío de paquetes de Windows está habilitado mediante la
    configuración IPEnableRouter, parte del tráfico puede evitar la
    ruta de procesamiento prevista por la aplicación. En consecuencia,
    los límites de ancho de banda podrían no aplicarse como se espera.
    La aplicación muestra el estado del reenvío; sigue las indicaciones
    que proporciona para esta configuración.
  - Los sistemas de malla (mesh) y otras redes con varias direcciones
    MAC de puerta de enlace solo son compatibles parcialmente.
    La aplicación realiza el seguimiento de una única identidad de
    puerta de enlace, que podría no cubrir todas las rutas de la red.
  - La aplicación no limita el tráfico que se origina en tu propia PC
    ni el que tiene como destino esa misma computadora.

--------------------------------------------------------------------
9. INICIO RÁPIDO
--------------------------------------------------------------------
  1. Ejecuta SelfishNetV2.exe. Si se deniega el acceso al controlador
     de paquetes, sigue las indicaciones para reiniciar la aplicación
     con permisos de administrador.
  2. Selecciona el adaptador de red conectado a la LAN donde se
     encuentran tu router o puerta de enlace predeterminada.
  3. Espera a que aparezcan los dispositivos automáticamente o
     presiona Discover para iniciar un escaneo inmediato.
  4. Introduce los límites de descarga y subida en la tabla de
     dispositivos, o activa Block para impedir que se reenvíe el
     tráfico de un dispositivo.
     Utiliza la casilla Spoof para incluir o excluir un dispositivo
     del control del tráfico. De forma predeterminada, todos los
     dispositivos están incluidos.
  5. Presiona Start Shaping para comenzar. El indicador de estado
     se pondrá verde cuando el control del tráfico esté activo.
  6. Presiona Stop antes de cerrar la aplicación para iniciar la
     restauración de la red. El cierre normal de la aplicación
     también activa este procedimiento.

Consejos:
  - Mantén la aplicación abierta mientras el control del tráfico esté
    activo. Al cerrarla, se detiene el control y se inicia la
    restauración de la red.
  - Si un límite parece no aplicarse, comprueba la configuración del
    dispositivo e intenta detener y reiniciar el control del tráfico.
    Aunque el motor lee los límites dinámicamente, reiniciarlo puede
    provocar un nuevo ciclo de suplantación ARP que ayude con los
    dispositivos que conservan asociaciones ARP contradictorias.
  - Utiliza el selector Legacy/Modern para comparar el comportamiento
    de la limitación por intervalos fijos y del control mediante
    depósito de tokens.

10. NOTA DE SEGURIDAD Y USO LEGAL
--------------------------------------------------------------------
Redirigir el tráfico de red de otro dispositivo es una operación intrusiva que puede interrumpir la conectividad y exponer el tráfico a interceptación. Utiliza SelfishNet únicamente en redes de tu propiedad o para las que tengas autorización expresa para realizar pruebas. Los autores no se hacen responsables del uso no autorizado o indebido de la aplicación.

Cuando se detiene normalmente, la aplicación intenta restablecer las asociaciones ARP originales de la red mediante correcciones unicast y anuncios ARP por broadcast. Estos mensajes ayudan a actualizar las cachés ARP, pero no se puede garantizar la restauración en todos los entornos de red, especialmente si la aplicación termina por la fuerza o los dispositivos rechazan los mensajes correctivos.
